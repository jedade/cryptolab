zk-SNARK & zk-STARK

Preuve à divulgation nulle Succincte · Non-interactive Zcash · Ethereum L2

📖 1. Présentation

zk-SNARK
2012 (Bitansky, Chiesa, Genkin, Tromer)
zk-STARK
2018 (Ben-Sasson, Bentov, Horesh, Riabzev)
Usage
Confidentialité + scalabilité blockchain

Les zk-SNARKs (Succinct Non-interactive ARguments of Knowledge) et zk-STARKs (Scalable Transparent ARguments of Knowledge) sont les ZKP industriels qui ont rendu possibles Zcash, les rollups Ethereum (zkSync, StarkNet, Linea), et l'identité décentralisée. Leur révolution : une preuve courte (~200 octets pour SNARK) vérifiable en quelques ms, qui atteste qu'un calcul a été effectué correctement sans dévoiler les entrées.

⚙️ 2. Fonctionnement

To prove "I correctly ran program P on private inputs", we transform P into:

1. Arithmetic circuit: equations over a finite field
2. R1CS / AIR: constraint system (Rank-1 Constraint System or Algebraic Intermediate Representation)
3. QAP / PLONK / FRI: polynomial transformation
4. Proof: polynomial commitment + random openings
5. Verification: bilinear pairing (SNARK) or Merkle hash (STARK)
zk-SNARK

Proof ~200-400 bytes · verify < 10 ms · BUT requires trusted setup per circuit (or universal for PLONK)

zk-STARK

Larger proof (~100 KB) BUT no trusted setup, post-quantum, more scalable for big computations

🧮 3. Mathématiques

Pinocchio (Groth16): proof = 3 elliptic points (~200 bytes)
PLONK: proof = 9 G₁ + 7 𝔽 (~400 bytes), universal trusted setup
STARK: proof = O(log²(N)) hashes via FRI (Fast Reed-Solomon IOP)

Les SNARKs reposent sur des hypothèses cryptographiques sur courbes elliptiques avec couplage (BLS12-381, BN254). Les STARKs reposent UNIQUEMENT sur les fonctions de hachage cryptographiques (SHA-256, Poseidon) → résistants quantique.

🌍 5. Cas réel : avantages, inconvénients, failles

✅ Avantages
  • Preuves ultra-courtes (200 o – 100 Ko)
  • Vérification en quelques ms
  • Confidentialité totale + intégrité prouvée
  • STARK : transparent + post-quantique
  • Base des rollups Ethereum (zkEVM)
⚠️ Inconvénients
  • Génération de preuve coûteuse (mémoire, CPU)
  • SNARK : trusted setup → confiance multi-parties
  • Compilation des circuits complexe (circom, halo2)
  • Bugs subtils dans les circuits = trous de sécurité
💥 Failles connues
  • Zcash counterfeiting bug (2018-2019) : faux ZEC pendant 5 mois
  • Cérémonie trusted setup compromise → faux proofs possibles
  • Tornado Cash : analyse de timing de dépôts/retraits
  • Sigma protocols bugs (Aurora 2021, Polygon zkEVM 2023)
  • FRI low-degree test : si mal paramétré, soundness trop faible
