Asymétrique Log discret Niveau intermédiaire

📖 1. Présentation

Inventeur
Taher Elgamal
Année
1985
Type
Asymétrique · DLP

Le cryptosystème ElGamal est un schéma asymétrique basé sur la difficulté du logarithme discret (DLP) dans un groupe cyclique. Inventé par Taher Elgamal en 1985, il existe en deux variantes : chiffrement (rarement utilisé tel quel) et signature (base de DSA, le standard NIST). Il a donné naissance à toute la famille DSA / ECDSA / Schnorr.

⚙️ 2. Fonctionnement

For ElGamal encryption, a public group (G, q, g) is fixed. Alice publishes her public key h = g^x mod p (x = private key). Bob encrypts m in two steps:

1. Bob picks random y and computes c₁ = g^y mod p
2. Bob computes c₂ = m · h^y mod p
3. He sends (c₁, c₂) to Alice
4. Alice decrypts: m = c₂ · c₁^(−x) mod p

Encryption is probabilistic (random y): the same m encrypted twice gives 2 different ciphertexts — crucial property (IND-CPA).

">

Pour le chiffrement ElGamal, on fixe un groupe public (G, q, g). Alice publie sa clé publique h = g^x mod p (x = clé privée). Bob chiffre m en deux temps :

1. Bob choisit y aléatoire et calcule c₁ = g^y mod p
2. Bob calcule c₂ = m · h^y mod p
3. Il envoie (c₁, c₂) à Alice
4. Alice déchiffre : m = c₂ · c₁^(−x) mod p

Le chiffrement est probabiliste (y aléatoire) : un même m chiffré 2 fois donne 2 chiffrés différents — propriété cruciale (IND-CPA).

🧮 3. Mathématiques

h = g^x mod p   (public key)
c₁ = g^y mod p  ·  c₂ = m · h^y mod p
m = c₂ / c₁^x = c₂ · g^(−xy) mod p
">
h = g^x mod p   (clé publique)
c₁ = g^y mod p  ·  c₂ = m · h^y mod p
m = c₂ / c₁^x = c₂ · g^(−xy) mod p

La sécurité repose sur la Decisional Diffie-Hellman (DDH) — distinguer (g, g^a, g^b, g^ab) de (g, g^a, g^b, g^r) est conjecturé difficile.

💻 4. Code

# Démo ElGamal (petits paramètres, à but pédagogique)
import secrets

p = 467   # premier
g = 2     # générateur
x = 153   # clé privée Alice
h = pow(g, x, p)   # clé publique : h = g^x mod p

# Chiffrement de m=331 par Bob
m = 331
y = secrets.randbelow(p-2) + 1
c1 = pow(g, y, p)
c2 = (m * pow(h, y, p)) % p
print(f"Chiffré: ({c1}, {c2})")

# Déchiffrement par Alice
s = pow(c1, x, p)
s_inv = pow(s, -1, p)        # inverse modulaire
m_back = (c2 * s_inv) % p
print(f"Déchiffré: {m_back}")  # 331
function modpow(b,e,m){let r=1n;b=((b%m)+m)%m;while(e>0n){if(e&1n)r=(r*b)%m;e>>=1n;b=(b*b)%m;}return r;}
function modinv(a,m){let[or,r]=[((a%m)+m)%m,m],[os,s]=[1n,0n];while(r){const q=or/r;[or,r]=[r,or-q*r];[os,s]=[s,os-q*s];}return((os%m)+m)%m;}

const p = 467n, g = 2n;
const x = 153n;
const h = modpow(g, x, p);

const m = 331n;
const y = 47n;
const c1 = modpow(g, y, p);
const c2 = (m * modpow(h, y, p)) % p;

const s = modpow(c1, x, p);
const m_back = (c2 * modinv(s, p)) % p;
console.log(m_back);  // 331n

🌍 5. Cas réel : avantages, inconvénients, failles

✅ Avantages
  • Probabiliste (IND-CPA)
  • Sécurité bien comprise (DDH)
  • Base de DSA, Schnorr, ECDSA
  • Homomorphe multiplicatif
⚠️ Inconvénients
  • Chiffré 2× plus grand que le clair
  • Lent (deux exponentiations modulaires)
  • Rarement utilisé directement (variante signature préférée)
  • Aléa de chiffrement critique : un y faible casse tout
💥 Failles connues
  • Réutilisation de y → récupération de la clé privée x
  • Attaque par malléabilité (homomorphisme multiplicatif non désiré)
  • Petits groupes < 2048 bits cassables (Logjam)
  • Shor (quantique) : casse le DLP en temps polynomial
