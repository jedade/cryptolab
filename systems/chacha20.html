ChaCha20

Chiffrement par flux ARX (Add-Rotate-XOR) TLS 1.3 · WireGuard

📖 1. Présentation

Auteur
Daniel J. Bernstein
Année
2008 (variant de Salsa20, 2005)
Famille
Chiffrement par flux ARX

ChaCha20 est un chiffrement par flux moderne, conçu pour être rapide en software pur (sans instructions matérielles dédiées comme AES-NI). Sur un téléphone ARM ou un microcontrôleur, il est souvent plus rapide qu'AES — d'où son adoption massive : TLS 1.3, WireGuard, OpenSSH, Tor, Signal.

Couplé à Poly1305 (MAC ultra-rapide de Bernstein aussi), il forme l'AEAD ChaCha20-Poly1305 — une des deux suites cryptographiques par défaut de TLS 1.3 (avec AES-GCM).

⚙️ 2. Fonctionnement

ChaCha20 ne chiffre pas directement : il génère un keystream pseudo-aléatoire qu'on XOR avec le clair.

On applique 20 rounds (10 colonnes + 10 diagonales) de la quarter-round, puis on additionne l'état initial à l'état final → 64 octets de keystream. On incrémente le counter et on recommence.

// Quarter-round ARX
a += b; d ^= a; d = rotl(d, 16);
c += d; b ^= c; b = rotl(b, 12);
a += b; d ^= a; d = rotl(d,  8);
c += d; b ^= c; b = rotl(b,  7);

ARX = Add (mod 2³²), Rotate, XOR. Trois opérations simples, parfaites pour les CPU. Pas de table → résistance naturelle aux side-channels par cache.

🧮 3. Spécifications

Key : 256 bits  ·  Nonce : 96 bits  ·  Counter : 32 bits
Bloc keystream : 64 octets  ·  Max data / (key, nonce) : 2³² blocs ≈ 256 Go
XChaCha20

Variant à nonce étendu (192 bits). Permet de générer un nonce purement aléatoire sans risque de collision.

ChaCha20-Poly1305

AEAD standardisé (RFC 8439). Chiffrement + tag d'authentification 128 bits.

💻 5. Code

# pip install cryptography
from cryptography.hazmat.primitives.ciphers.aead import ChaCha20Poly1305
import os

key = ChaCha20Poly1305.generate_key()      # 32 octets = 256 bits
nonce = os.urandom(12)                     # 96 bits
aead = ChaCha20Poly1305(key)

ciphertext = aead.encrypt(nonce, b"Hello CryptoLab", associated_data=b"meta")
plaintext  = aead.decrypt(nonce, ciphertext, associated_data=b"meta")
print(plaintext)  # b"Hello CryptoLab"

# XChaCha20 (nonce 192 bits aléatoire — pratique)
from nacl.secret import SecretBox
box = SecretBox(key)
encrypted = box.encrypt(b"Hello")          # nonce auto-géré
print(box.decrypt(encrypted))
// Node.js (Web Crypto ne supporte pas ChaCha20 nativement en 2026)
import { createCipheriv, createDecipheriv, randomBytes } from 'node:crypto';

const key   = randomBytes(32);   // 256 bits
const nonce = randomBytes(12);   // 96 bits
const aad   = Buffer.from('meta');

const cipher = createCipheriv('chacha20-poly1305', key, nonce, { authTagLength: 16 });
cipher.setAAD(aad);
const ct  = Buffer.concat([cipher.update('Hello CryptoLab'), cipher.final()]);
const tag = cipher.getAuthTag();

const decipher = createDecipheriv('chacha20-poly1305', key, nonce, { authTagLength: 16 });
decipher.setAAD(aad);
decipher.setAuthTag(tag);
const pt = Buffer.concat([decipher.update(ct), decipher.final()]);
console.log(pt.toString());  // Hello CryptoLab

🌍 6. Pourquoi ChaCha20 plutôt qu'AES ?

✓ Atouts
  • Rapide partout, surtout sans AES-NI (mobile, IoT)
  • ARX → résistance side-channel par cache intrinsèque
  • Pas de padding, pas de modes — c'est XOR
  • Construction simple : 100 lignes de C lisibles
  • Adopté Google (Android), Cloudflare, OpenSSH par défaut
✗ Pièges
  • Réutiliser un (key, nonce) = casse totale (XOR des 2 chiffrés révèle XOR des 2 clairs)
  • Le nonce 96 bits limite à 2⁹⁶/2 ≈ 4×10²⁸ messages avant collision
  • Toujours utiliser ChaCha20-Poly1305, jamais ChaCha20 nu
  • Grover : sécurité quantique 128 bits (comme AES-256)

💥 Failles & attaques connues

Vulnérabilités spécifiques, attaques connues, cassures historiques.

Réutilisation de nonce

XOR de 2 chiffrés = XOR de 2 clairs. Casse totale et instantanée.

ChaCha20 nu (sans Poly1305)

Pas d'authentification → forgery triviale. Toujours utiliser ChaCha20-Poly1305.

Nonce 96-bit aléatoire en grand volume

Collision après ~2⁴⁸ messages. Utiliser XChaCha20 (nonce 192-bit) si gros volume.

Algorithme de Grover (quantique)

256-bit clé → 128 bits post-quantique. Reste sûr (comme AES-256).

Mauvais générateur d'aléa pour la clé

Pas spécifique à ChaCha20 mais devastateur sur toute primitive symétrique.
