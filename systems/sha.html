SHA — Secure Hash Algorithms

Hash cryptographique Sens unique Niveau débutant

📖 1. Présentation

Une fonction de hachage cryptographique prend une donnée de taille quelconque et produit une empreinte de taille fixe — déterministe, à sens unique, et sensible au moindre bit modifié. La famille SHA (Secure Hash Algorithm) regroupe les principaux standards mondiaux.

SHA-1

🛑 Cassé (2017)
SHA-256
256 bits · SHA-2
✓ Standard actuel
SHA-512
512 bits · SHA-2
✓ Très utilisé
SHA-3 (Keccak)
2015 · construction éponge
✓ Alternative

⚙️ 2. Propriétés requises

1. Résistance à la préimage

Trouver M tel que H(M) = h est infaisable.

2. Seconde préimage

Étant donné M₁, trouver M₂ ≠ M₁ avec H(M₁)=H(M₂) est infaisable.

3. Résistance aux collisions

Trouver n'importe quels M₁ ≠ M₂ tels que H(M₁) = H(M₂) est infaisable.

Effet avalanche : changer 1 bit en entrée doit modifier environ 50% des bits en sortie.

🧮 3. Construction Merkle-Damgård (SHA-2)

SHA-256 itère une fonction de compression sur des blocs de 512 bits :

Hi = f(Hi−1, Mi)
avec H₀ = IV (valeur initiale fixe) et f = compression à 64 rounds

SHA-3 utilise une construction éponge totalement différente (Keccak), choisie par le NIST en 2012 pour offrir une alternative en cas de faille structurelle de SHA-2.

💻 5. Code

import hashlib

h = hashlib.sha256(b"CryptoLab 2026").hexdigest()
print(h)  # 64 caractères hex = 256 bits

# Hasher un fichier
def file_sha256(path):
    h = hashlib.sha256()
    with open(path, 'rb') as f:
        for chunk in iter(lambda: f.read(8192), b''):
            h.update(chunk)
    return h.hexdigest()

async function sha256(text) {
  const data = new TextEncoder().encode(text);
  const buf = await crypto.subtle.digest('SHA-256', data);
  return [...new Uint8Array(buf)]
    .map(b => b.toString(16).padStart(2,'0'))
    .join('');
}

// Hasher un fichier (Blob)
async function hashFile(file) {
  const buf = await file.arrayBuffer();
  const h = await crypto.subtle.digest('SHA-256', buf);
  return [...new Uint8Array(h)].map(b=>b.toString(16).padStart(2,'0')).join('');
}

🌍 6. Cas réel & limites

✓ Usages
  • Signatures numériques (hash puis signe)
  • Vérification d'intégrité (checksums, Merkle trees)
  • Bitcoin (double SHA-256 pour Proof of Work)
  • Git (identifiants SHA-1 → migration SHA-256)
  • HMAC (authentification)
✗ Pièges
  • NE JAMAIS sha256(password) seul → utiliser Argon2/bcrypt
  • Length-extension attack sur Merkle-Damgård (SHA-256 sans HMAC)
  • MD5 et SHA-1 cassés : interdits en sécurité
  • Grover divise par 2 → SHA-256 → 128 bits post-quantique

💥 Failles & attaques connues

Vulnérabilités spécifiques, attaques connues, cassures historiques.

Collisions MD5 (Wang 2004)

Collision en ~secondes sur CPU moderne. MD5 interdit en sécurité.

SHAttered (SHA-1, Google 2017)

110 années-GPU pour une collision. SHA-1 interdit depuis 2017.

Length-extension attack

SHA-256(secret ∥ message) permet d'étendre le hash → toujours utiliser HMAC.

Hash de mot de passe naïf

sha256(pw) cassable à 100 Gh/s sur GPU → utiliser Argon2id/bcrypt/scrypt.

Rainbow tables (sans sel)

Tables précalculées de hashes → 14 milliards d'entrées sur 4 Go.

Algorithme de Grover (quantique)

SHA-256 → 128 bits de sécurité collision. SHA-384/512 à privilégier long terme.
