📖 1. Présentation

La cryptographie sur courbes elliptiques (ECC) offre la même sécurité que RSA avec des clés bien plus petites : 256 bits ECC ≈ 3072 bits RSA. C'est pourquoi elle domine la cryptographie moderne — TLS 1.3, Bitcoin, Signal, SSH, identités mobiles.

⚙️ 2. Fonctionnement géométrique

Sur les réels, une courbe elliptique a l'allure de y² = x³ + ax + b. On définit une « addition » géométrique :

P + Q (deux points distincts)

Tracer la corde PQ : elle recoupe la courbe en un 3e point R. Le résultat P+Q est la symétrique de R par rapport à l'axe X.

2P (doublement)

Tracer la tangente en P. Elle recoupe la courbe en R. Le résultat 2P est la symétrique de R.

En cryptographie on travaille en arithmétique modulaire (corps fini 𝔽p), ce qui transforme la courbe continue en un nuage de points discrets — mais la loi d'addition reste valable algébriquement.

🧮 3. Mathématiques

y² ≡ x³ + ax + b (mod p)
avec 4a³ + 27b² ≢ 0 (mod p) pour éviter les singularités
k · G = Q
G = point générateur public, k = clé privée, Q = clé publique

Sécurité = ECDLP (Elliptic Curve Discrete Log Problem) : étant donné G et Q, retrouver k est exponentiellement difficile. Les meilleures attaques connues (Pollard rho) coûtent √n opérations.

📐 3 bis. Catalogue des courbes utilisées en production

Toutes les courbes ECC ne sont pas équivalentes. Forme géométrique, premier choisi, twist security, performance, résistance aux side-channels : chaque courbe a un compromis. Voici les principales en 2026 :

secp256k1
Weierstrass · Koblitz
SECG · 256 bits · y² = x³ + 7
  • Bitcoin, Ethereum, toutes blockchains majeures
  • Structure Koblitz (a=0) → optimisations d'endomorphisme GLV
  • Sécurité ≈ 128 bits
  • ⚠️ Pas générée de manière vérifiable (rigid) — préférée par paranoïa anti-NSA
P-256 (secp256r1, prime256v1)
Weierstrass · NIST
NIST FIPS 186 · 256 bits
  • Standard TLS, JWT, FIDO2, gouvernement US
  • Implémentation matérielle ultra-répandue (HSM, TPM, eID)
  • Sécurité ≈ 128 bits
  • ⚠️ Constantes choisies par la NSA — suspicions historiques (mais aucune attaque connue)
Curve25519 (X25519)
Montgomery · DJB
D.J. Bernstein, 2006 · 256 bits · y² = x³ + 486662x² + x sur 𝔽2²⁵⁵−19
  • Signal, WhatsApp, WireGuard, SSH OpenSSH, TLS 1.3, Tor v3
  • Conçue pour ECDH (X25519 = Montgomery ladder)
  • Constantes rigides et publiquement justifiées
  • Résistante aux side-channels par construction (ladder à temps constant)
  • Twist security : pas besoin de valider le point
Ed25519
Edwards · EdDSA
Bernstein et al., 2011 · 256 bits · forme tordue d'Edwards (équivalente à Curve25519)
  • Schéma de signature EdDSA, signatures 64 octets
  • Déterministe (pas besoin d'aléa de qualité à la signature)
  • SSH, Git, Tor, JWT, certificats X.509 modernes
  • Loi d'addition complète (pas de cas spéciaux à l'infini)
Curve448 / Ed448
Edwards · 224 bits sec
Hamburg, 2014 · 448 bits · cousine plus paranoïaque de Curve25519
  • ~224 bits de sécurité (vs 128 pour 25519)
  • X448 dans TLS 1.3 quand on veut overkill
  • Plus lente — usage spécifique (long terme, gouvernemental)
BLS12-381
Pairing-friendly
Barreto-Lynn-Scott · 381 bits · supporte le couplage bilinéaire
  • Ethereum 2.0 (Beacon chain, agrégation BLS)
  • Zcash Sapling, zk-SNARK
  • Permet les signatures agrégées BLS — N signatures → 1 signature
brainpoolP256r1 / 384r1
Weierstrass · Europe
RFC 5639 · constantes vérifiables (nothing-up-my-sleeve)
  • Préférée par certaines réglementations européennes (BSI)
  • Génération transparente des paramètres
  • Moins répandue que P-256, support limité
P-384 / P-521
Weierstrass · NIST · haute sécurité
NIST · 192 / 256 bits de sécurité
  • NSA Suite B (TOP SECRET)
  • Certificats gouvernementaux, défense
  • Plus lente — réservée aux usages haute assurance

🔍 3 grandes familles de formes

Weierstrass courte
y² = x³ + ax + b

Forme historique. Cas spéciaux (point à l'infini, doubling vs add). secp256k1, P-256, Brainpool.

Montgomery
By² = x³ + Ax² + x

Optimisée pour la « Montgomery ladder » : multiplication scalaire en temps constant, résistance side-channel intrinsèque. Curve25519.

Edwards (tordues)
ax² + y² = 1 + dx²y²

Loi d'addition unifiée et complète (pas de cas spéciaux), naturelle pour les signatures. Ed25519, Ed448.

// Courbe jouet pédagogique — pour la vraie crypto, utiliser Web Crypto
const P = 97n, A = 2n, B = 3n;

const modinv = (a, m) => {
  let [old_r, r] = [((a % m) + m) % m, m];
  let [old_s, s] = [1n, 0n];
  while (r !== 0n) {
    const q = old_r / r;
    [old_r, r] = [r, old_r - q*r];
    [old_s, s] = [s, old_s - q*s];
  }
  return ((old_s % m) + m) % m;
};

function add(P1, P2) {
  if (!P1) return P2; if (!P2) return P1;
  if (P1.x === P2.x && (P1.y + P2.y) % P === 0n) return null; // ∞
  let m;
  if (P1.x === P2.x && P1.y === P2.y)
    m = ((3n*P1.x*P1.x + A) * modinv(2n*P1.y, P)) % P;
  else
    m = ((P2.y - P1.y) * modinv((P2.x - P1.x + P) % P, P)) % P;
  const x3 = ((m*m - P1.x - P2.x) % P + P) % P;
  const y3 = ((m*(P1.x - x3) - P1.y) % P + P) % P;
  return { x: x3, y: y3 };
}

function mul(k, G) {
  let R = null, P = G;
  while (k > 0n) {
    if (k & 1n) R = add(R, P);
    P = add(P, P);
    k >>= 1n;
  }
  return R;
}

🌍 6. Cas réel & limites

✓ Omniprésent en 2026
  • TLS 1.3 par défaut (ECDHE, ECDSA)
  • Bitcoin (secp256k1), Ethereum, toutes blockchains
  • Signal Protocol (Curve25519, Ed25519)
  • Clés SSH ed25519
  • WireGuard, Tor, Apple iMessage
✗ Pièges
  • Mauvais générateur d'aléa = clé révélée (PlayStation 3 hack)
  • Courbes potentiellement « backdoorées » (méfiance autour de Dual_EC_DRBG)
  • Attaques side-channel sur scalar multiplication
  • Cassé par Shor sur ordinateur quantique

💥 Failles & attaques connues

Vulnérabilités spécifiques, attaques connues, cassures historiques.

Pollard rho (générique)

Meilleur algo classique pour ECDLP : O(√n) → curve256k1 = 2¹²⁸ opérations.

Side-channel sur multiplication scalaire

Timing, cache, EM emission → récupération de la clé privée (cf. attaques sur OpenSSL).

PlayStation 3 ECDSA hack (2010)

Sony réutilisait le même nonce → fail0verflow récupère la master signing key.

Invalid curve attack

Si on accepte un point pas sur la courbe, on peut le placer dans un petit sous-groupe → leak.

Dual_EC_DRBG (NSA backdoor)

Constantes choisies par la NSA permettant la prédiction de l'aléa.

Algorithme de Shor (quantique)

Casse ECDLP en temps polynomial → toutes courbes mortes.
