📖 1. Présentation

Inventeur
Carl Adam Petri
Année
1962 (thèse PhD)
Usage en crypto
Vérification de protocoles

Les réseaux de Petri ne sont PAS un cryptosystème — ce sont des modèles graphiques de systèmes concurrents (introduits par Carl Adam Petri en 1962). Leur lien avec la cryptographie : on les utilise pour modéliser et vérifier formellement des protocoles cryptographiques, détecter automatiquement des failles logiques (deadlocks, séquences interdites, attaques par rejeu, MITM).

⚙️ 2. Fonctionnement

A Petri net consists of:

Places (circles)

System states (e.g. "Alice waiting for ack", "shared key valid")

Transitions (bars)

Events (e.g. "send challenge", "verify signature")

Directed arcs

Flow between places and transitions (pre/post conditions)

Tokens (•)

Represent resources / in-flight messages

Crypto application: protocol verification. We model actors (Alice, Bob, Eve), their messages, their mental states. We mechanically explore all possible interleavings → we detect attacks never imagined.

Historical example: Needham-Schroeder (1995)

Gavin Lowe used a similar model-checking exploration (FDR) to discover, 17 years after publication, a MITM attack on the Needham-Schroeder protocol. Petri nets apply the same idea with graphical formalism.

🧮 3. Mathématiques

Net N = (P, T, F, M₀)
P = places · T = transitions · F ⊆ (P×T) ∪ (T×P) · M₀ = initial marking
Reachable state space from M₀ → exhaustive exploration to detect property violation (CTL/LTL)
">
Réseau N = (P, T, F, M₀)
P = ensemble de places · T = transitions · F ⊆ (P×T) ∪ (T×P) · M₀ = marquage initial
Espace d'états reachable depuis M₀ → exploration exhaustive pour détecter une violation de propriété (CTL/LTL)

Variantes utiles en crypto : colored Petri nets (jetons typés représentant nonces, clés, identités), timed Petri nets (modéliser timeouts, fenêtres de validité), stochastic Petri nets (probabilités d'attaque).

💻 4. Code

# Modélisation d'un protocole simple avec snakes (Python Petri nets)
# pip install snakes
from snakes.nets import *

n = PetriNet('Needham-Schroeder simplifié')

# Places : états des acteurs
n.add_place(Place('Alice_init', [dot]))
n.add_place(Place('Bob_init', [dot]))
n.add_place(Place('Eve_observe', []))
n.add_place(Place('Alice_sent_Na', []))
n.add_place(Place('Bob_received', []))

# Transition : Alice envoie son nonce
n.add_transition(Transition('Alice_send', Expression('True')))
n.add_input('Alice_init', 'Alice_send', Variable('x'))
n.add_output('Alice_sent_Na', 'Alice_send', Variable('x'))
n.add_output('Eve_observe', 'Alice_send', Expression("'Na'"))  # Eve écoute

# Transition : Bob reçoit
n.add_transition(Transition('Bob_recv', Expression('True')))
n.add_input('Alice_sent_Na', 'Bob_recv', Variable('x'))
n.add_input('Bob_init', 'Bob_recv', Variable('y'))
n.add_output('Bob_received', 'Bob_recv', Expression("(x, y)"))

# Explore l'espace d'états → cherche un marquage où Eve a appris la clé
graph = StateGraph(n)
graph.build()
print(f"États accessibles : {len(graph)}")

🌍 5. Cas réel : avantages, inconvénients, failles

✅ Avantages
  • Formalisme graphique intuitif
  • Détection automatique de séquences d'attaque
  • Exploration exhaustive des états du protocole
  • Variantes riches : colored, timed, stochastic
  • Théorie mature depuis 60 ans
⚠️ Inconvénients
  • Explosion combinatoire de l'espace d'états
  • Pas adapté aux primitives cryptographiques elles-mêmes (focus protocoles)
  • Outils dédiés (Tamarin, ProVerif) souvent préférés en pratique
  • Courbe d'apprentissage raide
💥 Failles connues
  • Pas de "failles" intrinsèques (ce n'est pas un crypto)
  • LIMITE pratique : ne capture pas les attaques par canal auxiliaire
  • LIMITE : modèle symbolique → manque les attaques cryptanalytiques fines
  • Bugs dans le modèle = sécurité prouvée mais système réel vulnérable
  • Exemples célèbres détectés : Needham-Schroeder MITM (Lowe 1995), 5G AKA (2018)
