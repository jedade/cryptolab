Diffie-Hellman

Échange de clés Logarithme discret Intermédiaire

📖 1. Présentation

Auteurs
Whitfield Diffie & Martin Hellman
Année
1976
Type
Protocole d'échange de clé

Diffie-Hellman (DH) est le premier protocole public permettant à deux parties — qui n'ont jamais communiqué auparavant — de générer une clé secrète commune en discutant sur un canal totalement ouvert. C'est l'acte fondateur de la cryptographie à clé publique. Ralph Merkle est souvent co-crédité.

Attention : DH n'est pas un chiffrement, c'est un mécanisme d'établissement de clé. La clé partagée sert ensuite à un chiffrement symétrique (AES, ChaCha20…).

⚙️ 2. Fonctionnement

Alice et Bob s'accordent publiquement sur deux nombres : un premier p et un générateur g. Chacun garde ensuite un secret.

👩 Alice
  • secret a
  • A = ga mod p
  • envoie A à Bob
  • K = Ba mod p
👁 Eve (espionne)

Voit passer : p, g, A, B

Pour retrouver K, il lui faudrait calculer le logarithme discret — pratiquement infaisable pour de grands p.

👨 Bob
  • secret b
  • B = gb mod p
  • envoie B à Alice
  • K = Ab mod p

Magie : Ab = (ga)b = gab = (gb)a = Ba  ⇒  même clé chez les deux.

🧮 3. Mathématiques

Public : p (premier), g (générateur de ℤ/pℤ*)
A = ga mod p   |   B = gb mod p
K = gab mod p

La sécurité repose sur le problème du logarithme discret (DLP) : connaissant g, p, A = ga mod p, retrouver a est exponentiellement difficile. Avec p ≥ 2048 bits, c'est hors de portée des ordinateurs classiques.

🔍 4. Simulation interactive

💻 5. Code

import secrets

p = 0xFFFFFFFFFFFFFFFFC90FDAA22168C234... # premier de 2048 bits (RFC 3526)
g = 2

# Alice
a = secrets.randbelow(p-2) + 1
A = pow(g, a, p)

# Bob
b = secrets.randbelow(p-2) + 1
B = pow(g, b, p)

# Échange : Alice envoie A, Bob envoie B
K_alice = pow(B, a, p)
K_bob   = pow(A, b, p)

assert K_alice == K_bob   # ✓ même clé partagée
function modpow(b, e, m) {
  let r = 1n; b = b % m;
  while (e > 0n) {
    if (e & 1n) r = (r * b) % m;
    e >>= 1n; b = (b * b) % m;
  }
  return r;
}

const p = 23n, g = 5n;

// Secrets locaux
const a = 6n, b = 15n;

// Envois publics
const A = modpow(g, a, p);   // 8
const B = modpow(g, b, p);   // 19

// Clé partagée
const K1 = modpow(B, a, p);  // 2
const K2 = modpow(A, b, p);  // 2

console.log(K1 === K2);  // true

🌍 6. Cas réel & limites

✓ Utilisations modernes
  • TLS 1.3 (handshake ECDHE — variante elliptique)
  • Signal Protocol (X3DH initial)
  • SSH (échange de clé de session)
  • WireGuard (basé sur Noise / Curve25519)
  • Forward secrecy : clés éphémères → passé protégé
✗ Pièges
  • DH brut ne s'authentifie PAS → MITM possible (Eve = faux Alice côté Bob)
  • Combiner avec signature (RSA, ECDSA) ou PSK
  • Logjam (2015) : petits groupes DH partagés vulnérables
  • Cassé par l'algorithme de Shor (post-quantique)

💥 Failles & attaques connues

Vulnérabilités spécifiques, attaques connues, cassures historiques.

Man-in-the-Middle (sans authentification)

Eve se fait passer pour Alice côté Bob et vice-versa. Solution : signer A et B.

Logjam (2015)

Petits groupes 512-bit partagés par défaut sur des millions de serveurs → précalcul GNFS.

Small subgroup attack

Si Eve envoie un B malicieux dans un sous-groupe d'ordre faible, elle apprend des bits de a.

Algorithme de Shor (quantique)

Casse le logarithme discret en temps polynomial → DH classique mort à moyen terme.

Mauvais RNG sur a, b

Si a est prévisible (Debian OpenSSL 2008), la clé partagée l'est aussi.
