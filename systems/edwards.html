Courbes d'Edwards

Courbe elliptique Forme tordue (twisted) Ed25519 · Ed448

📖 1. Présentation

Inventeur (forme mathématique)
Harold Edwards (2007)
Adapté en crypto par
Bernstein, Lange (2007)
Standardisé
Ed25519 (2011) · EdDSA RFC 8032

Les courbes d'Edwards sont une représentation alternative des courbes elliptiques, découverte par Harold Edwards en 2007. Adaptées en cryptographie quasi-immédiatement par Bernstein et Lange, leur forme tordue (twisted Edwards) a deux atouts décisifs : loi d'addition complète et unifiée (pas de cas spéciaux comme avec Weierstrass) et résistance side-channel intrinsèque. C'est sur cette forme qu'est bâtie Ed25519, le standard de signature moderne.

⚙️ 2. Fonctionnement

A twisted Edwards curve has the form:

a·x² + y² = 1 + d·x²·y²
with a, d ≠ 0 and a ≠ d, over a finite field 𝔽p

Unified, complete addition law:

(x₁, y₁) + (x₂, y₂) = ( (x₁y₂ + y₁x₂) / (1 + d·x₁x₂y₁y₂),   (y₁y₂ − a·x₁x₂) / (1 − d·x₁x₂y₁y₂) )
✓ SINGLE law

One formula for P+Q, P+P (doubling), and P+0 (identity). No conditional branch → natural constant time.

✓ No "point at infinity"

Identity is (0, 1), an ordinary point. Easier to implement, fewer bugs.

Curve25519 (Montgomery form) and Edwards25519 (Edwards form) are birationally equivalent — same curve from two angles. X25519 uses Montgomery (for x-only ECDH), Ed25519 uses Edwards (for EdDSA signatures).

Une courbe d'Edwards tordue a la forme :

a·x² + y² = 1 + d·x²·y²
avec a, d ≠ 0 et a ≠ d, sur un corps fini 𝔽p

Loi d'addition unifiée et complète :

(x₁, y₁) + (x₂, y₂) = ( (x₁y₂ + y₁x₂) / (1 + d·x₁x₂y₁y₂),   (y₁y₂ − a·x₁x₂) / (1 − d·x₁x₂y₁y₂) )
✓ Loi UNIQUE

Une seule formule pour P+Q, P+P (doublement), et P+0 (élément neutre). Pas de branche conditionnelle → temps constant naturel.

✓ Pas de "point à l'infini"

Le neutre est (0, 1), un point ordinaire. Plus simple à implémenter, moins de bugs.

Curve25519 (forme Montgomery) et Edwards25519 (forme Edwards) sont birationnellement équivalentes — c'est la même courbe sous deux angles. X25519 utilise la forme Montgomery (pour ECDH x-only), Ed25519 utilise la forme Edwards (pour les signatures EdDSA).

🧮 3. Mathématiques

Edwards25519 : −x² + y² = 1 + (−121665/121666)·x²·y²   (mod 2²⁵⁵−19)
Edwards448 (Goldilocks) : x² + y² = 1 − 39081·x²·y²   (mod 2⁴⁴⁸ − 2²²⁴ − 1)

Le coefficient a=−1 dans Ed25519 minimise le coût de l'addition. Edwards448 est conçu pour ~224 bits de sécurité (vs 128 pour Ed25519) — utilisé quand on veut overkill.

💻 4. Code

# Ed25519 en pratique
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey
from cryptography.hazmat.primitives import serialization

# Génération de clé
sk = Ed25519PrivateKey.generate()
pk = sk.public_key()

# Signature (déterministe — même clé + même message ⇒ même signature)
signature = sk.sign(b"Hello, Edwards!")
print(len(signature))    # 64 octets — clé publique 32 octets

# Vérification
pk.verify(signature, b"Hello, Edwards!")

# Sérialisation : format Raw (32 octets) ou PEM (PKCS#8)
pub_raw = pk.public_bytes(
    serialization.Encoding.Raw,
    serialization.PublicFormat.Raw)
print(pub_raw.hex())   # 64 chars hex

# Ed448 quand on veut 224 bits de sécurité (paranoïaque ou réglementaire)
from cryptography.hazmat.primitives.asymmetric.ed448 import Ed448PrivateKey
sk448 = Ed448PrivateKey.generate()
sig448 = sk448.sign(b"long-term archive")
# 114 octets pour Ed448
// Ed25519 dans Web Crypto API (support 2023+)
const kp = await crypto.subtle.generateKey(
  { name: 'Ed25519' }, true, ['sign', 'verify']
);

const msg = new TextEncoder().encode('Hello, Edwards!');
const sig = new Uint8Array(await crypto.subtle.sign('Ed25519', kp.privateKey, msg));

// La signature est toujours de 64 octets
console.log(sig.length);   // 64

const ok = await crypto.subtle.verify('Ed25519', kp.publicKey, sig, msg);
console.log(ok);           // true

// Export de la clé publique brute (32 octets)
const rawPub = new Uint8Array(await crypto.subtle.exportKey('raw', kp.publicKey));
console.log(rawPub.length); // 32

🌍 5. Cas réel : avantages, inconvénients, failles

✅ Avantages
  • Loi d'addition unifiée → temps constant naturel
  • Pas de point à l'infini → moins de bugs
  • Signatures EdDSA déterministes
  • Très rapide en software pur
  • Standard moderne : SSH, Git, JWT, Tor v3
⚠️ Inconvénients
  • Moins intuitive géométriquement que Weierstrass
  • Support hardware limité dans certains HSM legacy
  • Cofacteur 8 → attention au clamping
  • Toujours pas dans certaines normes gouvernementales (mais EdDSA est dans FIPS 186-5)
💥 Failles connues
  • Mauvaise implémentation : clamping oublié → small-subgroup attacks
  • Ed25519 batch verification bugs (libsodium 2019)
  • Confusion entre Ed25519 (sign) et X25519 (DH) → mauvais usage
  • Mauvaise dérivation du nonce déterministe si entropie compromise
  • Shor (quantique) : casse Ed25519/Ed448 → migration PQC
