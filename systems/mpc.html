1979 · Shamir

MPC & partage de secret de Shamir

Multi-parties Seuil (t, n) Intermédiaire

📖 1. Présentation

Le calcul multi-parties sécurisé (MPC) permet à plusieurs participants de calculer une fonction sur leurs entrées privées sans révéler ces entrées les uns aux autres. La brique fondamentale est le partage de secret à seuil publié par Adi Shamir en 1979.

Schéma (t, n) : un secret S est divisé en n parts. t parts suffisent pour reconstruire S. t−1 parts ne révèlent aucune information sur S (sécurité parfaite, information-théorique).

⚙️ 2. Principe — polynômes

Le dealer choisit un polynôme aléatoire de degré t−1 dont le terme constant est le secret :

P(x) = S + a₁·x + a₂·x² + … + at−1·xt−1 (mod p)

Les parts distribuées sont (1, P(1)), (2, P(2)), …, (n, P(n)). Tout polynôme de degré t−1 est uniquement déterminé par t points : interpolation de Lagrange retrouve S = P(0).

🧮 3. Interpolation de Lagrange

S = P(0) = Σ yi · Li(0)
Li(0) = Πj ≠ i (−xj) / (xi − xj)

Tout est calculé modulo un grand premier p pour rester dans un corps fini.

💻 5. Code

import random

def split(secret, n, t, p):
    coeffs = [secret] + [random.randint(0, p-1) for _ in range(t-1)]
    return [(i, sum(c * pow(i, k, p) for k, c in enumerate(coeffs)) % p)
            for i in range(1, n+1)]

def reconstruct(shares, p):
    secret = 0
    for j, (xj, yj) in enumerate(shares):
        num, den = 1, 1
        for k, (xk, _) in enumerate(shares):
            if k != j:
                num = (num * (-xk)) % p
                den = (den * (xj - xk)) % p
        secret = (secret + yj * num * pow(den, -1, p)) % p
    return secret

shares = split(1234, n=5, t=3, p=100003)
print(reconstruct(shares[:3], 100003))   # 1234
function modinv(a, p) {
  let [or, r] = [((a % p) + p) % p, p], [os, s] = [1n, 0n];
  while (r) { const q = or / r; [or, r] = [r, or - q*r]; [os, s] = [s, os - q*s]; }
  return ((os % p) + p) % p;
}
function modpow(b, e, m) { let r=1n; b=((b%m)+m)%m; while(e>0n){if(e&1n)r=(r*b)%m;e>>=1n;b=(b*b)%m;} return r; }

function split(secret, n, t, p) {
  const coeffs = [secret];
  for (let i=1; i<t; i++) coeffs.push(BigInt(Math.floor(Math.random()*Number(p))));
  const shares = [];
  for (let i=1n; i<=BigInt(n); i++) {
    let y = 0n;
    for (let k=0; k<t; k++) y = (y + coeffs[k] * modpow(i, BigInt(k), p)) % p;
    shares.push([i, y]);
  }
  return shares;
}

function reconstruct(shares, p) {
  let secret = 0n;
  for (let j=0; j<shares.length; j++) {
    const [xj, yj] = shares[j];
    let num = 1n, den = 1n;
    for (let k=0; k<shares.length; k++) if (k !== j) {
      num = (num * (-shares[k][0] + p*100n)) % p;
      den = (den * ((xj - shares[k][0] + p*100n) % p)) % p;
    }
    secret = (secret + yj * num % p * modinv(den, p)) % p;
  }
  return secret;
}

🌍 6. Cas réel

✓ Usages
  • Wallets MPC (Fireblocks, Coinbase Custody)
  • Signatures à seuil FROST (Bitcoin)
  • Cérémonies trusted setup (Zcash)
  • Récupération de clé (SSSS, Trezor Shamir Backup)
  • Coffres-forts d'entreprise (Vault, HashiCorp)
✗ Pièges
  • Mauvais générateur d'aléa → coefficients prévisibles
  • Sans authentification, les parts peuvent être falsifiées (VSS, PVSS résolvent)
  • MPC complet a un coût communication élevé
  • Définir t/n incorrect (trop bas → fragilité, trop haut → dispo)

💥 Failles & attaques connues

Vulnérabilités spécifiques, attaques connues, cassures historiques.

Parts non authentifiées

Sans VSS/PVSS, un dealer malveillant peut donner des parts incohérentes → mauvaise reconstruction.

Mauvaise aléa pour les coefficients

Si les a_i sont prévisibles, le polynôme l'est aussi → secret deviné avec moins de t parts.

Side-channel sur la reconstruction

Timing révèle quelles parts ont été utilisées.

t/n mal choisi

t trop bas = fragilité (compromis d'un seul nœud), t trop haut = disponibilité menacée.

Attaque Byzantine sur MPC

Participants malhonnêtes peuvent biaiser le résultat sans MPC robuste (SPDZ, BGW).
