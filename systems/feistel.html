Réseaux de Feistel

Structure générique DES · Blowfish · Twofish Niveau intermédiaire

📖 1. Présentation

Un réseau de Feistel n'est pas un cryptosystème, c'est une structure générique pour construire un chiffrement par blocs. Conçu par Horst Feistel chez IBM en 1971 pour le projet Lucifer, il a été popularisé par DES (1977) puis repris par des dizaines d'algorithmes : Blowfish, Twofish, RC5, RC6, CAST, MISTY, GOST, Camellia.

Sa propriété magique : la fonction interne F n'a pas besoin d'être inversible. C'est une liberté de conception énorme — on peut y mettre n'importe quelle fonction (S-box, addition modulaire, hash…) et obtenir un chiffrement parfaitement réversible.

⚠️ Petite clarification : à ne pas confondre avec les réseaux de Petri (qui sont des modèles de concurrence en informatique théorique, sans lien avec la crypto).

⚙️ 2. Fonctionnement

On divise chaque bloc de plaintext en deux moitiés de même taille (L₀, R₀). À chaque round i ∈ [1, n] :

Li = Ri−1
Ri = Li−1 ⊕ F(Ri−1, Ki)

Le bloc chiffré final est (Ln, Rn). Pour déchiffrer, on applique exactement la même structure mais en parcourant les sous-clés à l'envers :

Ri−1 = Li
Li−1 = Ri ⊕ F(Li, Ki)
💡 Cœur de la magie : F peut être quelconque (non-inversible, non-bijective, asymétrique). Seules les sous-clés et leur ordre changent entre chiffrement et déchiffrement.

🧮 3. Pourquoi ça marche

Démonstration en 1 round (les n rounds suivent par induction) :

Chiffrement : L₁ = R₀ ; R₁ = L₀ ⊕ F(R₀, K)
Déchiffrement avec (L₁, R₁) :
R₀' = L₁ = R₀ ✓
L₀' = R₁ ⊕ F(L₁, K) = (L₀ ⊕ F(R₀, K)) ⊕ F(R₀, K) = L₀ ✓

Le XOR est sa propre inverse : a ⊕ b ⊕ b = a. C'est ce qui permet de récupérer L₀ sans jamais inverser F.

📋 5. Algorithmes basés sur Feistel

DES (1977)

Bloc 64 / clé 56 bits / 16 rounds. F = expansion + XOR clé + 8 S-boxes + permutation. Cassé en 1998.

3DES (1998)

DES appliqué 3 fois (encrypt-decrypt-encrypt) avec 3 clés. Toléré pour legacy, déprécié 2024.

Blowfish (1993)

Bruce Schneier · bloc 64 / clé jusqu'à 448 bits / 16 rounds. Libre, populaire dans bcrypt.

Twofish (1998)

Successeur de Blowfish, finaliste AES. Bloc 128 / clé 128-256 / 16 rounds.

Camellia (2000)

Mitsubishi/NTT · alternative à AES standardisée ISO, RFC 3713. Bloc 128, structure mixte Feistel.

GOST 28147-89

Standard soviétique/russe. Bloc 64 / clé 256 / 32 rounds. S-boxes définies localement.

Variantes notables :
  • Feistel déséquilibré (Skipjack) : L et R de tailles différentes
  • Generalized Feistel : plus de 2 branches (RC6, CAST-256)
  • ARX (ChaCha20, Speck) : autre paradigme, sans Feistel

💻 6. Code (Feistel générique)

def feistel(block, subkeys, F, decrypt=False):
    """Chiffre/déchiffre un bloc via un réseau de Feistel.
    F : fonction (R, K) -> bloc même taille que R."""
    L, R = block
    keys = list(reversed(subkeys)) if decrypt else subkeys
    for K in keys:
        L, R = R, L ^ F(R, K)
    return (R, L)            # swap final pour symétrie

# Exemple avec F triviale (NON sécurisée — illustration uniquement)
def F(R, K):
    return ((R + K) ^ ((R << 3) | (R >> 13))) & 0xFFFF

subkeys = [0x42a3, 0x9f01, 0xbeef, 0x1337]
ct = feistel((0xcafe, 0xbabe), subkeys, F)
pt = feistel(ct, subkeys, F, decrypt=True)
assert pt == (0xcafe, 0xbabe)
function feistel([L, R], subkeys, F, decrypt = false) {
  const keys = decrypt ? [...subkeys].reverse() : subkeys;
  for (const K of keys) {
    [L, R] = [R, (L ^ F(R, K)) & 0xFFFF];
  }
  return [R, L];               // swap final
}

const F = (R, K) => ((R + K) ^ ((R << 3) | (R >> 13))) & 0xFFFF;
const subkeys = [0x42a3, 0x9f01, 0xbeef, 0x1337];

const ct = feistel([0xcafe, 0xbabe], subkeys, F);
const pt = feistel(ct, subkeys, F, true);
console.log(pt);   // [0xcafe, 0xbabe]

🌍 7. Forces & limites

✓ Forces
  • Structure simple, prouvée par 50 ans d'analyse
  • F peut être tout sauf trivialement linéaire
  • Chiffrement = déchiffrement (même code)
  • Permet hardware compact (clé reverse facile)
✗ Limites
  • Bloc 64 bits insuffisant (Sweet32) → AES = SPN 128
  • Moins parallélisable que SPN (rounds séquentiels)
  • Diffusion plus lente que SPN (Avalanche en n/2 rounds)
  • Choix moderne pour blocs cipher = SPN (AES)

💥 Failles & attaques connues

Vulnérabilités spécifiques, attaques connues, cassures historiques.

Linear cryptanalysis (Matsui, 1993)

Trouve des approximations linéaires des S-boxes pour casser DES avec 2⁴³ paires.

Differential cryptanalysis (Biham-Shamir)

Observe la propagation de différences à travers les rounds — DES casse en 2⁴⁷.

Sweet32 (2016)

Collisions de blocs en mode CBC pour les chiffrements 64-bit (Blowfish, 3DES) → ~32 Go suffisent.

Brute force DES (EFF, 1998)

56 bits → cassés en 56h par DES Cracker. 3DES déprécié 2024.
