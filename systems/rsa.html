RSA

Asymétrique Factorisation Niveau intermédiaire

📖 1. Présentation

Inventeurs
Rivest, Shamir, Adleman
Année
1977 (MIT)
Type
Asymétrique à clé publique

RSA est le premier algorithme à clé publique opérationnel et reste l'un des plus utilisés au monde (TLS, signatures, certificats). Sa sécurité repose sur un fait mathématique simple : multiplier deux grands nombres premiers est facile, mais retrouver ces nombres premiers à partir du produit est extrêmement difficile.

Fait amusant : Clifford Cocks (GCHQ britannique) avait découvert un schéma équivalent en 1973 — mais il était classifié et n'a été révélé qu'en 1997.

⚙️ 2. Fonctionnement

RSA suit trois étapes : génération des clés, chiffrement, déchiffrement.

1. Génération
  • Choisir 2 grands premiers p, q
  • n = p · q
  • φ(n) = (p−1)(q−1)
  • e copremier avec φ(n)
  • d ≡ e⁻¹ (mod φ(n))
→ Clé pub : (n, e)
→ Clé priv : (n, d)
2. Chiffrement
Avec la clé publique du destinataire :
c = me mod n
3. Déchiffrement
Avec sa propre clé privée :
m = cd mod n

🧮 3. Mathématiques

n = p · q
φ(n) = (p−1)(q−1)
e · d ≡ 1 (mod φ(n))
c = me mod n   |   m = cd mod n

Pourquoi ça marche ? Grâce au théorème d'Euler : si pgcd(m, n) = 1, alors mφ(n) ≡ 1 (mod n). Donc me·d = m1 + k·φ(n) ≡ m (mod n). La sécurité repose sur la difficulté de calculer φ(n) sans connaître p et q — ce qui revient à factoriser n.

💻 5. Code

from math import gcd

def modinv(a, m):
    # Inverse modulaire via Euclide étendu
    g, x, _ = ext_gcd(a, m)
    if g != 1: raise ValueError("Pas d'inverse")
    return x % m

def ext_gcd(a, b):
    if a == 0: return b, 0, 1
    g, x, y = ext_gcd(b % a, a)
    return g, y - (b // a) * x, x

# Génération
p, q = 61, 53
n = p * q              # 3233
phi = (p-1) * (q-1)    # 3120
e = 17
d = modinv(e, phi)     # 2753

# Chiffrement / déchiffrement (pow utilise l'exponentiation rapide)
m = 65
c = pow(m, e, n)       # m^e mod n  = 2790
m2 = pow(c, d, n)      # c^d mod n  = 65
print(c, m2)
function modpow(b, e, m) {
  let r = 1n; b = b % m;
  while (e > 0n) {
    if (e & 1n) r = (r * b) % m;
    e >>= 1n;
    b = (b * b) % m;
  }
  return r;
}

function modinv(a, m) {
  let [old_r, r] = [a, m];
  let [old_s, s] = [1n, 0n];
  while (r !== 0n) {
    const q = old_r / r;
    [old_r, r] = [r, old_r - q * r];
    [old_s, s] = [s, old_s - q * s];
  }
  return ((old_s % m) + m) % m;
}

const p = 61n, q = 53n;
const n = p * q;                  // 3233n
const phi = (p - 1n) * (q - 1n);  // 3120n
const e = 17n;
const d = modinv(e, phi);         // 2753n

const m = 65n;
const c = modpow(m, e, n);        // 2790n
const m2 = modpow(c, d, n);       // 65n
console.log(c, m2);

🌍 6. Cas réel & limites

✓ Utilisations actuelles
  • TLS / HTTPS (échange initial, signatures)
  • Certificats X.509 (CA, navigateurs)
  • Signatures de paquets / firmware
  • PGP / GnuPG (e-mail chiffré)
  • SSH (clés RSA 2048/4096 bits)
✗ Pièges & limites
  • Lent → réservé à l'échange de clé / signature
  • Clés < 2048 bits : déconseillées (NIST)
  • Sans padding (OAEP/PSS) : vulnérable
  • e trop petit + même m envoyé : attaque de Håstad
  • Cassé par un ordinateur quantique (Shor)

💥 Failles & attaques connues

Vulnérabilités spécifiques, attaques connues, cassures historiques.

Bleichenbacher (1998) / ROBOT (2017)

Padding oracle PKCS#1 v1.5 → récupération de la clé privée serveur. ROBOT a touché F5, Citrix, Cisco.

Coppersmith (e petit)

Si on chiffre le même message m avec e=3 vers 3 destinataires, m est récupéré via CRT.

Fermat (p, q proches)

Si |p − q| est petit, on factorise n en quelques secondes (Bug 2012 : 0.4% des clés TLS).

ROCA (CVE-2017-15361)

Bug Infineon RSALib : clés de 760 mio cartes/TPM/eID factorisables.

Manger attack (OAEP)

Timing sur le déchiffrement OAEP révèle le plaintext.

Algorithme de Shor (quantique)

Factorise n en temps polynomial → toute clé RSA cassée instantanément.
