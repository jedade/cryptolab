AES — Advanced Encryption Standard

Symétrique Chiffrement par blocs Standard mondial

📖 1. Présentation

Inventeurs (Rijndael)
Joan Daemen & Vincent Rijmen
Standardisation
2001 (FIPS 197)
Type
Blocs 128 bits · clés 128/192/256

AES est le standard mondial de chiffrement symétrique. Il a été sélectionné par le NIST après une compétition publique (1997–2000) pour remplacer DES. Le candidat gagnant, Rijndael, est rapide en logiciel comme en matériel (jeu d'instructions AES-NI sur tous les CPU modernes), et résiste à toutes les attaques connues depuis 25 ans.

⚙️ 2. Fonctionnement

AES chiffre des blocs de 128 bits via 10, 12 ou 14 rounds selon la taille de clé. Chaque round applique 4 transformations sur un état 4×4 octets :

🔀
SubBytes

Substitution non-linéaire octet par octet via la S-box (inverse dans GF(2⁸)).

↔️
ShiftRows

Décalage cyclique des lignes : 0, 1, 2, 3 positions.

🧮
MixColumns

Mélange linéaire de chaque colonne via une matrice MDS dans GF(2⁸).

🔑
AddRoundKey

XOR avec la sous-clé du round (dérivée par le KeySchedule).

Le dernier round omet MixColumns. La clé est étendue en sous-clés par le key schedule.

🧮 3. Mathématiques — GF(2⁸)

Tous les calculs internes se font dans le corps de Galois GF(2⁸), c'est-à-dire les polynômes de degré ≤ 7 à coefficients dans {0, 1}, modulo le polynôme irréductible :

x⁸ + x⁴ + x³ + x + 1
(0x11B en hexadécimal)

La S-box est l'inverse multiplicatif dans GF(2⁸) suivi d'une transformation affine. MixColumns multiplie chaque colonne par une matrice fixe dans ce même corps.

💻 5. Code

# pip install cryptography
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
import os

key = AESGCM.generate_key(bit_length=256)  # 32 octets
nonce = os.urandom(12)                     # 96 bits recommandés pour GCM
aead = AESGCM(key)

ct = aead.encrypt(nonce, b"Hello AES", associated_data=b"meta")
pt = aead.decrypt(nonce, ct, associated_data=b"meta")
print(pt)  # b"Hello AES"

# Variante haut niveau : Fernet (AES-CBC + HMAC, gestion clé incluse)
from cryptography.fernet import Fernet
f = Fernet(Fernet.generate_key())
token = f.encrypt(b"Secret")
print(f.decrypt(token))
async function aesEncrypt(password, plaintext) {
  const enc = new TextEncoder();
  const salt = crypto.getRandomValues(new Uint8Array(16));
  const iv = crypto.getRandomValues(new Uint8Array(12));

  const baseKey = await crypto.subtle.importKey(
    'raw', enc.encode(password), 'PBKDF2', false, ['deriveKey']);
  const key = await crypto.subtle.deriveKey(
    {name:'PBKDF2', salt, iterations:100000, hash:'SHA-256'},
    baseKey, {name:'AES-GCM', length:256}, false, ['encrypt']);

  const ct = await crypto.subtle.encrypt(
    {name:'AES-GCM', iv}, key, enc.encode(plaintext));
  return { salt, iv, ct: new Uint8Array(ct) };
}

🌍 6. Cas réel & limites

✓ Omniprésent
  • TLS 1.3 (AES-GCM), Wi-Fi (WPA2/WPA3)
  • Disques chiffrés : FileVault, BitLocker, LUKS
  • VPN (IPsec, OpenVPN), SSH
  • Messageries (Signal, WhatsApp) — sous le capot
  • Approuvé NSA jusqu'au TOP SECRET (256 bits)
✗ Pièges d'implémentation
  • ECB : à fuir absolument (l'image du pingouin)
  • Réutilisation d'IV/nonce en GCM = catastrophe (récupération clé)
  • Attaques par canal auxiliaire (timing, cache)
  • Grover divise la sécurité par 2 → préférer AES-256 post-quantique

💥 Failles & attaques connues

Vulnérabilités spécifiques, attaques connues, cassures historiques.

Réutilisation de nonce en GCM

Forbidden Attack (Joux 2016) → récupération de la clé d'authentification.

Mode ECB (le pingouin Tux)

Patterns visibles dans le chiffré : à NE JAMAIS utiliser pour des données structurées.

Padding oracle (CBC sans MAC)

POODLE (2014), Lucky13 — déchiffrement octet par octet via réponses serveur.

Cache-timing sur AES software

Bernstein (2005) : extraction de clé sur serveur web partagé via cache L1.

Algorithme de Grover (quantique)

Recherche √n → AES-128 → 64 bits de sécurité. Migration AES-256 obligatoire long terme.

Mauvaise gestion des clés

Clé en clair en config, dans Git, en logs → casse opérationnelle la plus fréquente.
