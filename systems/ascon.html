Ascon — Cryptographie légère

AEAD léger Sponge IoT · RFID · MCU

📖 1. Présentation

Auteurs
Dobraunig, Eichlseder, Mendel, Schläffer
Conception
2014 (TU Graz / Infineon)
Standard
NIST Lightweight 2023

Ascon est une famille d'algorithmes AEAD et de hachage optimisée pour les environnements ultra-contraints : capteurs IoT, badges RFID, cartes à puce, microcontrôleurs. En 2023, après une compétition de 6 ans et 56 candidats, le NIST l'a sélectionné comme standard de cryptographie légère — équivalent IoT du concours AES.

Atouts : petite empreinte hardware (≈2 600 GE en ASIC), faible RAM (320 bits d'état total), résistance side-channel facilitée par sa structure et un seul appel de permutation pour chiffrer + authentifier.

⚙️ 2. La construction « sponge »

Ascon repose sur le paradigme sponge (popularisé par Keccak/SHA-3) :

1.
Initialisation : on construit un état de 320 bits = IV (64) ∥ clé (128) ∥ nonce (128) puis on applique une permutation pa (12 rounds).
2.
Associated data : on XOR chaque bloc d'AD dans la partie « rate » (64 bits) puis on applique pb (6 rounds).
3.
Plaintext : on XOR avec le rate, on extrait le ciphertext, on applique pb.
4.
Finalisation : on XOR à nouveau la clé, on applique pa, et on extrait le tag d'authentification (128 bits).
💡 Une seule primitive (la permutation) réalise à la fois chiffrement, authentification et hachage. Idéal quand l'espace de code est compté en kilo-octets.

🧮 3. Permutation Ascon-p

Chaque round = 3 couches sur l'état de 5 mots de 64 bits :

Addition de constante
x₂ ^= round_constant

Casse les symétries.

Substitution (S-box 5 bits)

Appliquée bit-tranche sur les 5 mots. Non-linéarité.

Diffusion linéaire
xᵢ ^= rot(xᵢ, a) ^ rot(xᵢ, b)

Mélange à l'intérieur de chaque mot.

💻 6. Code

# pip install ascon
import ascon, os

key   = os.urandom(16)        # 128 bits pour Ascon-128
nonce = os.urandom(16)        # 128 bits
ad    = b"sensor:42"          # données associées (authentifiées mais non chiffrées)

ciphertext = ascon.encrypt(key, nonce, ad, b"temperature=23.4C", variant="Ascon-128")
plaintext  = ascon.decrypt(key, nonce, ad, ciphertext, variant="Ascon-128")
print(plaintext)   # b"temperature=23.4C"

# Hachage
digest = ascon.hash(b"firmware.bin contents", variant="Ascon-Hash")
print(digest.hex())
// Référence officielle https://github.com/ascon/ascon-c
// Code typique pour MCU Cortex-M0 (~3 Ko Flash)
#include "api.h"
#include "ascon.h"

int crypto_aead_encrypt(
    unsigned char *c, unsigned long long *clen,
    const unsigned char *m, unsigned long long mlen,
    const unsigned char *ad, unsigned long long adlen,
    const unsigned char *nsec,
    const unsigned char *npub,
    const unsigned char *k)
{
    state_t s;
    ascon_initaead(&s, k, npub);
    ascon_adata(&s, ad, adlen);
    ascon_encrypt(&s, c, m, mlen);
    ascon_final(&s, k);
    /* Tag d'authentification 128 bits à la fin du chiffré */
    STOREBYTES(c + mlen, s.x[3], 8);
    STOREBYTES(c + mlen + 8, s.x[4], 8);
    *clen = mlen + CRYPTO_ABYTES;
    return 0;
}

🌍 7. Cas d'usage

✓ Là où AES est trop lourd
  • Capteurs sans-fil (LoRaWAN, BLE, Zigbee)
  • Cartes à puce, passeports biométriques
  • Tags RFID actifs
  • Firmware sécurisé sur Cortex-M0 / RISC-V tiny
  • Implants médicaux (pacemaker, pompes insuline)
✗ Ce qu'il ne remplace pas
  • AES-NI sur un serveur (AES y est plus rapide)
  • Asymétrique (ECC pour échange/signature)
  • Hashing volumineux (SHA-256 reste plus rapide en software gros CPU)

💥 Failles & attaques connues

Vulnérabilités spécifiques, attaques connues, cassures historiques.

Réutilisation de nonce

Comme tout AEAD, casse totale si (clé, nonce) répété.

Side-channel sur la permutation

Implémentations naïves software vulnérables au cache-timing.

Variante avec rounds réduits

Recommandation Ascon-128 (12/6 rounds) — toute baisse compromet la sécurité.

Algorithme de Grover (quantique)

Ascon-128 → 64 bits post-quantique. Utiliser Ascon-80pq (clé 160 bits) si besoin long terme.
