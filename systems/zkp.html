Zero-Knowledge Proofs

Preuve sans divulgation Protocole interactif Avancé

📖 1. Présentation

Auteurs
Goldwasser, Micali, Rackoff
Année
1985
Acronyme
ZKP

Une preuve à divulgation nulle permet à un prouveur (Peggy) de convaincre un vérificateur (Victor) qu'elle connaît un secret — sans révéler quoi que ce soit d'autre que la véracité de cette affirmation.

Trois propriétés fondamentales :

Complétude

Si Peggy connaît, Victor accepte (presque) toujours.

Solidité (soundness)

Si Peggy ne connaît pas, elle ne peut tricher qu'avec une probabilité négligeable.

Zero-knowledge

Victor n'apprend rien d'autre que la véracité.

⚙️ 2. La caverne d'Ali Baba

Imagine une caverne en boucle, avec une porte magique à l'extrémité. La porte s'ouvre sur un mot de passe.

  1. Peggy entre seule dans la caverne et choisit aléatoirement le couloir A ou B.
  2. Victor arrive à l'entrée et crie : « Sors par A ! » ou « Sors par B ! » (au hasard).
  3. Si Peggy connaît le mot magique, elle peut toujours sortir du bon côté (utiliser la porte si besoin).
  4. Si elle ne le connaît pas, elle réussit avec probabilité ½.
  5. Après n répétitions, la probabilité de tricher = 1/2n → bientôt négligeable.
Victor finit convaincu que Peggy connaît le mot — sans jamais l'entendre.

🧮 3. Mathématiques (Schnorr simplifié)

Prouver qu'on connaît x tel que y = gx mod p :

1. Peggy choisit r aléatoire, envoie t = gr mod p
2. Victor envoie un défi c aléatoire
3. Peggy répond s = r + c·x mod (p−1)
Victor vérifie : gs ≡ t · yc (mod p)

Si Peggy connaît x, l'équation est satisfaite. Sinon, elle aurait dû deviner c à l'avance — improbable.

💻 5. Code (Schnorr)

import secrets

def schnorr(p, g, x):
    # Peggy
    r = secrets.randbelow(p-1)
    t = pow(g, r, p)
    # Victor
    c = secrets.randbelow(p-1)
    # Peggy répond
    s = (r + c*x) % (p-1)
    # Victor vérifie
    y = pow(g, x, p)
    lhs = pow(g, s, p)
    rhs = (t * pow(y, c, p)) % p
    return lhs == rhs

assert schnorr(p=23, g=5, x=7)
function modpow(b,e,m){let r=1n;b=b%m;while(e>0n){if(e&1n)r=(r*b)%m;e>>=1n;b=(b*b)%m;}return r;}

function schnorr(p, g, x, c) {
  // Peggy choisit r, calcule t = g^r mod p
  const r = BigInt(Math.floor(Math.random() * Number(p-1n)));
  const t = modpow(g, r, p);
  // Peggy répond : s = r + c·x mod (p-1)
  const s = (r + c*x) % (p - 1n);
  // Victor vérifie : g^s == t · y^c mod p
  const y = modpow(g, x, p);
  const lhs = modpow(g, s, p);
  const rhs = (t * modpow(y, c, p)) % p;
  return { t, s, y, valid: lhs === rhs };
}

🌍 6. Cas réel

✓ Usages modernes
  • Zcash, Monero — transactions privées
  • zk-Rollups Ethereum (StarkNet, zkSync)
  • Identité décentralisée (preuve d'âge sans révéler la date)
  • Authentification sans mot de passe
  • Conformité KYC privée
✗ Pièges
  • zk-SNARK : nécessite un trusted setup (cérémonie multi-parties)
  • Preuves coûteuses à générer (mémoire, CPU)
  • Implémentations subtiles, sujettes à bugs critiques
  • L'aléa du prouveur doit rester secret

💥 Failles & attaques connues

Vulnérabilités spécifiques, attaques connues, cassures historiques.

Trusted setup compromis (zk-SNARK)

Si tous les participants à la cérémonie sont corrompus → preuves forgeable.

Mauvais aléa du prouveur

Réutilisation de l'aléa (r) → extraction du secret (cf. cassures de schémas Σ).

Soundness error trop élevée

Un seul round Schnorr → 50% de cheat possible. Itérations Fiat-Shamir critiques.

Bugs d'implémentation des circuits

Snarky circuits : bugs ont permis de fausses preuves (Zcash counterfeiting 2018-2019).
