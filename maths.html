1. Arithmétique modulaire — le langage de la crypto

On dit que a ≡ b (mod n) si a et b ont le même reste dans la division par n. Les entiers sont « repliés » sur un cercle de longueur n. Toutes les opérations classiques (+, −, ×) restent valides, mais la division demande l'existence d'un inverse.

17 + 9 ≡ 2 (mod 24)  ·  7 × 8 ≡ 1 (mod 11)  ·  (−1) ≡ 25 (mod 26)

🎯 Application

Le chiffre de César : C(x) = (x + k) mod 26. RSA : c = me mod n. Diffie-Hellman : A = ga mod p.

🐍 Python

# Python has the % operator and pow(base, exp, mod)
print((17 + 9) % 24)       # 2
print(pow(7, -1, 11))      # 8  (inverse of 7 mod 11)
print(pow(2, 100, 1_000))  # 376  (fast modular exponentiation)

2. Nombres premiers — les briques fondamentales

Un nombre premier p est divisible seulement par 1 et lui-même. La sécurité de RSA repose sur le fait que multiplier deux grands premiers est trivial, mais factoriser leur produit est conjecturé exponentiel. Tests modernes : Miller-Rabin (probabiliste, ultra-rapide), AKS (déterministe, lent), ECPP (certificat de primalité).

π(n) ≈ n / ln(n)   (théorème des nombres premiers — densité de premiers près de n)

🎯 Application

Trouver un premier de 2048 bits ne prend que ~1s : on tire un grand entier aléatoire impair, on le teste Miller-Rabin 40 fois. Erreur ≤ 2⁻⁸⁰.

🐍 Python

from sympy import isprime, nextprime, randprime

print(isprime(2**521 - 1))           # True — Mersenne prime
print(nextprime(10**10))             # 10000000019
print(randprime(2**1023, 2**1024))   # 1024-bit prime

# Miller-Rabin (essence)
import random
def miller_rabin(n, k=40):
    if n < 2 or n % 2 == 0: return n == 2
    r, d = 0, n - 1
    while d % 2 == 0: d //= 2; r += 1
    for _ in range(k):
        a = random.randrange(2, n - 1)
        x = pow(a, d, n)
        if x in (1, n - 1): continue
        for _ in range(r - 1):
            x = pow(x, 2, n)
            if x == n - 1: break
        else:
            return False
    return True

3. Algorithme d'Euclide étendu & inverse modulaire

L'algorithme d'Euclide calcule pgcd(a, b) en O(log(min(a,b))). La version étendue trouve aussi x, y tels que ax + by = pgcd(a, b) — d'où l'inverse modulaire : si pgcd(a, n) = 1, alors a·x ≡ 1 (mod n).

gcd(252, 105) = gcd(105, 42) = gcd(42, 21) = 21
3 · 4 = 12 ≡ 1 (mod 11) → inverse de 3 mod 11 = 4

🎯 Application

Génération de la clé privée RSA : d ≡ e⁻¹ (mod φ(n)). Sans Euclide étendu, RSA serait inutilisable. 

def ext_gcd(a, b):
    if a == 0: return b, 0, 1
    g, x1, y1 = ext_gcd(b % a, a)
    return g, y1 - (b // a) * x1, x1

def modinv(a, m):
    g, x, _ = ext_gcd(a % m, m)
    if g != 1: raise ValueError("No inverse")
    return x % m

print(modinv(17, 3120))   # 2753  (RSA private key d for e=17, φ=3120)

4. Théorèmes d'Euler et de Fermat

Théorème de Fermat : si p premier et pgcd(a, p) = 1, alors a^(p−1) ≡ 1 (mod p). Généralisation par Euler : pour tout n et a copremier avec n, a^φ(n) ≡ 1 (mod n), où φ(n) est l'indicatrice d'Euler (nombre d'entiers de 1 à n copremiers avec n).

φ(p) = p − 1  ·  φ(p·q) = (p−1)(q−1) pour p, q premiers distincts
a^φ(n) ≡ 1 (mod n) ⇒ m^(ed) = m^(1 + kφ(n)) ≡ m (mod n) ← cœur de RSA

🎯 Application

Toute la correction de RSA repose sur Euler. Et le test de Fermat est l'ancêtre des tests de primalité probabilistes. 

from sympy import totient
print(totient(35))                # 24 = (5-1)*(7-1)
print(pow(11, totient(35), 35))   # 1 ✓
# Decrypt RSA :
n, e, p, q = 3233, 17, 61, 53
phi = (p-1)*(q-1)                 # 3120
d = pow(e, -1, phi)               # 2753
m = 65
c = pow(m, e, n)                  # 2790
m2 = pow(c, d, n)                 # 65 ✓

5. Groupes, anneaux, corps

Un groupe (G, ⋆) : opération associative, élément neutre, chaque élément a un inverse. Abélien si ⋆ est commutative. Un anneau ajoute une seconde opération (× distributive sur +). Un corps est un anneau où tout élément non nul a un inverse multiplicatif (on peut diviser).

(ℤ/nℤ, +)

Groupe abélien — additions modulo n.

(ℤ/pℤ)*

Groupe multiplicatif des inversibles. Cyclique d'ordre p−1. Base de DH.

(E(𝔽p), +)

Points d'une courbe elliptique sur 𝔽p. Cœur d'ECC.

Pourquoi c'est important ? La cryptographie asymétrique opère essentiellement dans des groupes cycliques où le logarithme discret est conjecturé difficile.

6. Logarithme discret (DLP)

Étant donné un générateur g d'un groupe cyclique d'ordre n et un élément h, trouver l'unique x ∈ [0, n−1] tel que gx = h est appelé le problème du logarithme discret. Conjecturé exponentiel pour les groupes bien choisis.

Diffie-Hellman, ElGamal, DSA, Schnorr
DH : A = ga mod p   ·   retrouver a à partir de A = DLP

Meilleurs algorithmes connus : Pollard rho (O(√n)), Baby-step Giant-step, GNFS pour les groupes 𝔽p* avec petit p. Aucun n'est polynomial — sauf pour les ordinateurs quantiques (Shor). 

# Baby-step giant-step for DLP (group of order n)
import math

def dlp(g, h, p):
    n = p - 1
    m = math.isqrt(n) + 1
    table = {pow(g, j, p): j for j in range(m)}
    inv = pow(g, -m, p)
    val = h
    for i in range(m):
        if val in table:
            return i * m + table[val]
        val = (val * inv) % p

print(dlp(5, 8, 23))   # 6 : 5^6 mod 23 = 8

7. Courbes elliptiques

Une courbe elliptique est l'ensemble des points (x, y) vérifiant y² = x³ + ax + b sur un corps fini, plus un « point à l'infini ». L'addition de points (règle de la corde-tangente) en fait un groupe abélien. Le DLP sur ce groupe est conjecturé plus difficile que le DLP classique → clés plus courtes pour la même sécurité.

y² = x³ + ax + b (mod p)
256 bits ECC ≈ 3072 bits RSA ≈ 128 bits AES de sécurité

Voir la page ECC pour les formules détaillées d'addition et de doublement, et Montgomery pour la forme optimisée.

8. Corps de Galois GF(2ⁿ)

Pour AES on travaille dans GF(2⁸) : les 256 polynômes binaires de degré ≤ 7, additionnés/multipliés modulo le polynôme irréductible x⁸ + x⁴ + x³ + x + 1 (0x11B). Ces opérations sont l'équivalent du « + et × » mais sur des octets.

a + b = a XOR b  ·  a · b = polynômes binaires modulo x⁸ + x⁴ + x³ + x + 1
# GF(2⁸) multiplication — used in AES MixColumns
def gmul(a, b):
    p = 0
    for _ in range(8):
        if b & 1: p ^= a
        hi = a & 0x80
        a = (a << 1) & 0xFF
        if hi: a ^= 0x1B    # reduction modulo x⁸ + x⁴ + x³ + x + 1
        b >>= 1
    return p

print(hex(gmul(0x57, 0x83)))  # 0xc1 — FIPS 197 example

9. Réseaux euclidiens (lattices)

Un réseau est l'ensemble de toutes les combinaisons entières d'un ensemble de vecteurs (sa base). Sur ces réseaux, les problèmes SVP (Shortest Vector) et CVP (Closest Vector) sont NP-difficiles. La cryptographie post-quantique (Kyber, Dilithium) repose sur leur version « bruitée » : LWE (Learning With Errors).

b = A · s + e (mod q) ← LWE
Sans bruit : retrouver s = facile. Avec bruit : conjecturé difficile (y compris quantique).

Voir la page Post-quantique pour une simulation.

10. Entropie & aléa cryptographique

L'entropie de Shannon mesure l'imprévisibilité d'une source en bits. Une clé n-bits doit avoir vraiment n bits d'entropie pour résister au brute force. D'où l'usage de CSPRNG : /dev/urandom (Linux), BCryptGenRandom (Windows), SecRandomCopyBytes (macOS), os.urandom en Python.

H(X) = − Σ pi · log₂(pi)
import os, secrets

# Best practice: SECRETS (default CSPRNG)
key = secrets.token_bytes(32)     # 256 bits of entropy
token = secrets.token_urlsafe(32) # URL-safe base64

# Bad practice: standard random (NOT cryptographic)
# import random ; key = random.getrandbits(256)   # predictable !

11. Complexité algorithmique

La sécurité d'un cryptosystème = écart entre le coût de l'utilisation légitime (polynomial) et le coût de l'attaque (espéré exponentiel). Une attaque à 2¹²⁸ opérations est infaisable : tout l'univers calculant à 10²⁰ ops/s mettrait encore 10²⁰ ans.

2⁸⁰
Plus vraiment safe
2¹²⁸
Standard (AES-128, ECC 256)
2²⁵⁶
Overkill (post-Grover safe)

12. Paradoxe des anniversaires

Dans un groupe de seulement 23 personnes, deux ont plus de 50% de chances de partager un anniversaire. Généralisation cryptographique : dans un espace de N hashes possibles, une collision apparaît avec probabilité 50% après ~√N tirages. C'est pourquoi un hash de n bits offre seulement n/2 bits de sécurité collision (SHA-256 → 128 bits collision).

P(collision avec k tirages dans N) ≈ 1 − e−k²/(2N)
# Empirical verification
import hashlib, secrets

seen = {}
i = 0
while True:
    i += 1
    h = hashlib.sha256(secrets.token_bytes(8)).digest()[:3]   # truncated to 24 bits
    if h in seen:
        print(f"Collision after {i} draws (expected ~{int((2**24)**0.5)})")
        break
    seen[h] = i
